# Agent Tracer 项目总体说明

## 项目定位

Agent Tracer 面向使用大语言模型和工具调用的智能体系统。它把 OpenTelemetry（OTel）Trace 统一转换为可分析的数据结构，再构建带有因果关系的执行图，用于定位异常步骤、判断根因、保留故障相关证据，并通过 Web 页面和多层监控接口展示结果。

项目的核心思路是：先保留 Trace 中的时间顺序、父子调用关系、工具结果和语义校验信息，再把这些信息组织为 `Intent`、`Planning`、`Action`、`Fact`、`Conclusion`、`Error` 等节点，以及 `Temporal`、`Call`、`Observation`、`Retry`、`Cognitive` 和语义传播边。根因分析阶段优先围绕最终结论或终止错误反向抽取故障路径，从而减少无关上下文对诊断的干扰。

## 处理链路

1. **Trace 接入与标准化**：`trace_input_adapter.py` 兼容不同 OTel/JSON 表达，将输入整理为统一的 Span 树。
2. **语义校验**：`semantic_trace_validator.py` 检查工具调用状态、参数模式、结果存在性、HTTP 状态、日期一致性、参数来源和结果传播情况。
3. **因果图构建**：`OTL_trace.py` 从 Span 和语义观察中生成节点与边，并输出图、摘要和诊断所需的中间结构。
4. **目标导向剪枝**：`agenttrace_target_pruning.py` 从最终答案或终止错误开始反向切片，保留故障邻域、重试上下文、规划到动作的桥接节点，同时按异常分数和时间多样性补充高价值节点。
5. **根因诊断**：`deepseek_judge_trace.py` 使用原始 Trace、全图或剪枝图进行 LLM 辅助判因；`diagnostic_report.py` 负责结构化诊断报告和 Markdown 导出。
6. **多层监控**：`multilayer_monitor.py` 聚合硬件层、虚拟化层、通信层和应用层指标；`monitoring_store.py` 提供事件接收、查询和快照接口。
7. **展示与批处理**：`web_app.py` 提供 Trace 上传、图分析和监控 API；`pipeline_run.py`、`run_all_in_one.py` 和 `run_single_trace_pipeline.py` 提供批量或分阶段执行入口。

## 代码阅读入口

- Web 服务：`web_app.py`
- Trace 解析：`trace_input_adapter.py`、`OTL_trace.py`
- 故障识别：`semantic_trace_validator.py`、`agenttrace_target_pruning.py`
- LLM 判因：`deepseek_judge_trace.py`
- 监控：`multilayer_monitor.py`、`monitoring_store.py`
- 命令行包装：`src/agent_tracer/cli.py`
- 故障特征目录：`config/fault_features.json` 和 `docs/故障特征说明.md`

## 项目边界

本仓库提供分析引擎和部署所需的核心代码，不包含业务 Trace、数据集、历史运行结果、API 密钥或论文材料。模型服务地址和密钥通过环境变量或本地 `.env` 注入。
