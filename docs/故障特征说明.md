# Agent Tracer 故障特征与分类扩展

本文把项目已有的 CCG 故障分类、代码中可直接核验的 Trace 规则，以及外部 AgentOps/云端可观测性框架放在同一张图景下说明。AWS 文档描述的是生产观测面和运维指标，并非一份学术意义上的 Agent 根因分类标准；因此本项目借鉴其指标与追踪维度，同时保留自身基于因果图的故障类别。

## 1. 分类原则与证据等级

根因不能由一个孤立关键词直接确定。规则会输出候选类别、支持该候选的 Span ID、置信度和人工复核标记，并区分三种证据：

- **直接可观测**：明确的错误状态、协议错误、参数契约违反、日期冲突等，可由当前 Trace 规则检测。
- **结构性候选**：重复动作、错误传播、未消费结果等依赖多个 Span 或因果边；规则可筛候选，但仍需检查上下文。
- **语义待验证**：约束遗漏、无证据结论、关键事实忽略、噪声误导等，不能仅由当前 span 名或关键词可靠决定，需要 LLM/人工、任务契约或反事实证据。

任何一类诊断都应沿“异常信号 → 发生位置 → 上下游依赖与传播 → 最终答案影响”给出证据。基础设施指标能解释环境背景，但不能单独证明某个 Agent 根因。

## 2. 基于 CCG 的 12 类 Agent 故障

项目既有的分类表将故障组织为意图理解、推理规划、工具交互和信息感知四个阶段，并以 Intent、Planning、Action、Fact、Conclusion、Error 节点及 Temporal、Call、Observation、Retry、Cognitive 边表达轨迹。细分模式如下。

| ID | 类别 | 典型轨迹证据 | 当前自动化状态 |
| --- | --- | --- | --- |
| F1 | 约束遗漏 | 用户给出时间、格式、精度等约束，后续规划或结论缺少约束传播；回答违反约束 | 日期不匹配已有直接校验；通用约束遗漏需任务契约/语义复核 |
| F2 | 知识幻觉 / 无证据结论 | 结论缺少相关 Fact 支撑，主要沿 Intent/Planning 直接到 Conclusion | 需评估结论与证据语义关联；不以“短链”直接判定 |
| F3 | 动作循环 / 思维死锁 | 相同工具与规范化参数多次重复，Retry 或相似 Action-Fact 子图持续出现 | 当前规则对完全相同工具和输入重复至少 3 次生成复核候选 |
| F4 | 动作执行崩溃 | Action 后出现工具错误状态、HTTP 错误、异常或超时 | 工具状态和语义校验 violation 可直接触发 |
| F5 | 工具幻觉 / 能力越界 | 调用不存在、未注册或不可用工具，环境明确拒绝 | 已加入拒绝文本规则；需工具注册表才能更可靠地区分 |
| F6 | 关键事实忽略 | 关键工具结果已产生，却未被后续模型/工具消费，结论未使用它 | 未消费结果生成低置信度候选；“关键”仍需语义判断 |
| F7 | 噪声干扰 / 错误归因 | 结论依赖无关或误导事实，关键事实连接弱或缺失 | 需要相关性/反事实判断；当前不自动硬判 |
| F8 | 格式协议失配 | LLM/Planning 输出缺少强制标签、无效 JSON、协议或 schema 错误 | 已加入 span 文本规则，并与现有语义错误校验并行 |
| F9 | 工具接口模式失配 | 必填参数缺失、参数类型/字段错误、参数对象与结果对象不一致 | 缺失参数和显式字段不一致已有确定性校验；来源不可追溯单独输出复核候选 |
| F10 | 错误放大型重试 | 同一工具和输入多次执行，重复尝试都关联执行失败，且没有有效修复 | 已对精确重复且多次失败生成候选；相似输入和恢复效果仍需增强 |
| F11 | 错误后继续作答 | 错误 Span 后仍出现 final-answer Span，回答未等待新事实或验证 | 已加入位置顺序候选；错误是否已恢复必须复核 |
| F12 | 级联外显错误 | 多个 Error Span 指向同一父动作，呈现 ToolArgError → TypeError → AgentExecutionError 等错误簇 | 已将共享父 Span 的错误簇作为候选；聚簇不代表多个独立根因 |

F1–F7 是较高层的 Agent 行为和证据使用问题；F8–F12 是此前结合项目 Trace 样本总结的工程细粒度模式。类别可以同时出现，例如一次错误参数调用（F9）可能引发级联外显（F12），之后又触发错误放大型重试（F10）。

## 3. AWS AgentCore 可观测性对照

截至 2026-09-24 查阅的 AWS Bedrock AgentCore 官方可观测性文档，AWS 强调使用 OTel 兼容遥测检查 Agent 工作流步骤、中间输出、执行路径和失败；并通过 CloudWatch 展示会话数、延迟、执行时长、Token 使用量和错误率，支持按元数据过滤、查看 Trace 与错误分布。该设计可补齐本项目的**运行态观察面**，对应关系如下：

| AWS / AgentOps 运维观察面 | Agent Tracer 对应能力 | 建议拓展 |
| --- | --- | --- |
| 工作流 Trace、每步中间输出 | Span 树、Intent/Planning/Action/Fact/Conclusion 图 | 保留 Session、Agent、模型、工具、部署版本等资源标签，按 session/agent 过滤 |
| 延迟、时长、错误率 | 通信层 Span 时延、错误状态、重试计数；硬件/通信四层监控 | 按 Agent/工具/模型聚合 P50/P95、成功率、超时率及重试率 |
| Token 使用量 | Judge 流程与模型调用统计 | 将 prompt/completion token、模型名和估算/实测成本挂到 Trace 与任务结果 |
| 质量与输出检查 | 语义校验、结论/证据链、失败分类 | 记录任务成功、约束满足、证据覆盖等任务级评价，不与基础设施告警混为一谈 |
| 元数据过滤、错误分析 | monitoring store 事件查询和 Trace 图 | 规范化 resource attributes，支持按环境、版本、模型、工具及错误类型过滤 |

AWS 官方运维指标不是故障分类本身。本项目在这层之上增加 F1–F12 的 Agent 行为分类和因果证据路径，使“运行出现了错误”进一步关联到“哪个动作或证据链导致最终影响”。

## 4. 近年 AgentOps 文献如何映射到代码

1. **AgentOps: Enabling Observability of LLM Agents（2024）**提出跨生命周期追踪 Agent 工件和运行数据，以增强可观测性。对本项目的启示是，Span 除了名字和输出，还要携带稳定的任务、Agent、模型、工具、版本和会话身份；本仓库已有 OTel 解析和因果图，可继续补标签标准化。
2. **Taming Uncertainty via Automation: Observing, Analyzing, and Optimizing Agentic AI Systems（ASE 2025；arXiv 2025）**将 AgentOps 描述为行为观察、指标收集、问题检测、根因分析、优化建议和运行时自动化的闭环。当前仓库覆盖前四阶段的一部分，也生成修复建议；自动化改写或线上执行应保留人工审批与回滚。
3. **A Survey on Evaluation of LLM-based Agents（Findings of ACL 2026）**从能力、任务基准、通用 Agent、指标和工具等角度梳理评估，并指出安全性、鲁棒性、成本效率和可扩展细粒度评估仍是缺口。对本项目的启示是将诊断质量、任务结果、延迟、Token/成本分开记录，并使用带标注 Trace 评估分类器，而不是把规则命中数当作效果。

这些来源支持“加强观测、分层评价和闭环运维”的设计方向，不代表本项目已实现所有论文提出的能力，也不为 F1–F12 的检测准确率背书。

## 5. 本仓库已经落入代码的扩展

- `fault_taxonomy.py`：面向 Trace 的保守签名检测器，将能确定的规则整理为结构化候选；返回 `fault_id`、类别、置信度、证据 Span、证据类型和 `requires_review`。
- `semantic_trace_validator.py`：把 `fault_taxonomy_findings` 放入语义分析结果，复用已有的参数契约、HTTP、时间与传播校验结果。
- `deepseek_judge_trace.py`：将规则候选附加到 Judge 的 Trace 摘要中，供 LLM 结合上下文核对，而非覆盖 Judge 结论。
- `config/fault_features.json`：机器可读的分类目录，标注类别、触发依据、实现状态和证据要求。
- `tests/test_fault_taxonomy.py`：验证直接错误、重复失败、终局错误顺序和不可观测类别不会被硬判。

对无法由 Trace 单独识别的 F1、F2、F7，检测器采取“不猜测”的策略。F6、F11、F3、F10、F12 当前只输出候选并要求复核；后续需要对齐 span 父子关系、结果消费链接、任务约束和因果图边，才能提高置信度。

## 6. 后续优先级

1. **完善错误层级与根错误聚合**：用 trace_id/span_id、父 Span、时间邻近、错误类型和消息指纹聚合 F12，区分根错误与派生错误。
2. **循环和恢复效果**：由完全相同调用扩展为规范化参数、工具、结果相似度及 Retry 边；区分有进展的探索与无效重试。
3. **终局答案门控**：确认错误是否被后续成功重试/新事实消解，再判断 F11，而非只依靠 Span 顺序。
4. **约束和证据覆盖**：从用户任务抽取显式约束，检查约束是否进入规划、动作、事实和结论；验证最终断言对事实的支持/冲突，服务 F1/F2/F6/F7。
5. **AgentOps 指标闭环**：记录任务成功率、工具成功率、错误率、重试率、延迟、Token/成本和版本标签；按照模型、Agent、工具、环境分组评估。
6. **标注与阈值校准**：在独立标注集上报告各类 precision/recall、置信度校准和跨数据集表现；在此之前，启发式分数只作为候选排序信号。
