# Agent Tracer 故障特征说明

下面的故障特征来自代码中已经实现的确定性校验、关键词先验、图结构规则和四层监控指标。它们是诊断线索，不等同于单个指标触发后的绝对结论；最终根因需要结合时间顺序、调用关系、结果传播和最终答案影响范围判断。

## 1. 工具执行与接口故障

### 1.1 工具执行失败

典型信号包括 Span 状态为 `error` 或 `status_code_error`、结果中的 `success=false`、存在明确 `error` 字段，或出现“tool execution failed”等强错误表达。代码会生成 `tool_execution_failure`，通常标记为高严重度。

### 1.2 HTTP / 服务端错误

工具结果中出现 `Status: 4xx/5xx` 时，代码生成 `http_failure`。常见解释包括资源不存在、权限不足、未授权、服务不可用或服务端异常。相关文本关键词还包括 `404`、`403`、`500`、`forbidden`、`unauthorized` 和 `service unavailable`。

### 1.3 参数模式错误

当工具声明了必填参数而调用输入缺少参数时，生成 `missing_required_argument`。当输入参数中的 `entity`、`location`、`resource_id` 等字段与返回结果不一致时，生成 `argument_result_mismatch`，用于识别调用对象错误或结果串线。

### 1.4 空结果与格式错误

工具调用成功但返回值为空时，生成 `empty_tool_result`。结果无法按预期解析、JSON 或工具调用格式不符合约束时，结合 `format`、`json`、`schema`、`parameter` 等信号判断为工具协议或输出格式风险。

## 2. 语义与证据链故障

### 2.1 时间或日期不一致

如果任务上下文要求某个日期，而工具结果只包含其他日期，生成 `temporal_mismatch`。这类错误常见于查询了错误日期、使用过期数据或把历史结果当作当前结果。

### 2.2 参数来源不可追溯

工具参数中出现无法在用户任务或此前工具证据中找到来源的不透明标识符时，生成 `ungrounded_tool_argument`。该问题表示参数可能由模型臆造、错误复制或跨任务污染；代码会将其判为 `uncertain`，并要求进一步语义复核。

### 2.3 结果未被消费或传播错误

系统追踪工具结果是否被后续模型或工具使用，记录 `NOT_EXPOSED`、`EXPOSED`、`PROPAGATED`、`TRANSFORMED`、`REJECTED` 等传播状态。故障证据如果没有进入最终答案，可能是无效中间结果；错误证据如果被传播到最终答案，则具有更高根因优先级。

### 2.4 语义拒绝与矛盾

图中的 `SemanticOrigin`、`SemanticValidation`、`SemanticPropagation`、`SemanticRejection` 和 `EvidenceExposure` 边用于表达证据产生、验证、传播、拒绝和暴露。`entity_mismatch`、`argument_result_mismatch`、`temporal_mismatch` 等语义类型通常比单纯的文本关键词更适合定位根因。

## 3. Agent 推理与恢复故障

### 3.1 重试与恢复失败

文本或边中出现 `retry`、`again`、`re-run`、`rerun`、`try another` 等信号时，代码识别重试上下文。若多次重试仍通向同一错误，或重试没有改变参数、证据和状态，通常归为 `retry_or_recovery_failure`。

### 3.2 规划漂移与动作偏离

`need to`、`should`、`next`、`instead`、`verify`、`rethink` 等规划词与 Action/Fact 的不一致，可作为规划漂移线索。图剪枝会保留 Planning 到 Action 的桥接节点，以便判断错误是出在计划、执行还是工具返回。

### 3.3 最终答案不收敛

`Conclusion` 或最终答案附近出现 `error`、`invalid`、`wrong`、`contradiction`、`no evidence`、`hallucination` 等表达，或最终结论直接依赖一个高风险错误节点时，代码会优先选择该终止结论/错误作为诊断目标。

## 4. 系统与基础设施故障

多层监控将系统信号分成四层：

- **硬件层**：CPU、内存、磁盘、主机名和平台信息。高 CPU、内存压力、磁盘空间不足可能造成超时、排队或进程失败。
- **虚拟化层**：容器、Kubernetes、云环境、主机和服务资源属性。资源身份变化、容器重启或部署关系异常可能造成 Trace 断裂和服务不可达。
- **通信层**：Client/Server/Producer/Consumer Span、HTTP/RPC/消息语义、调用边、错误率、重试次数和 P50/P95 延迟。延迟上升、错误率升高或重试集中通常指向网络、依赖服务或消息链路问题。
- **应用层**：Agent、LLM、工具调用、错误节点和因果图规模。应用层用于把基础设施症状与具体 Agent 步骤、工具和最终答案关联起来。

## 5. 诊断使用原则

故障定位应按“异常信号 → 发生位置 → 上下游传播 → 最终影响”组织证据。单独的 `timeout`、`failed` 或高延迟只能作为候选线索；当它同时满足错误节点/语义违反、时间上位于终止错误之前、并且错误结果传播到最终答案时，才应提高为主要根因候选。
